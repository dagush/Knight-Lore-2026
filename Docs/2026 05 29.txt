Knight Lore Semantic Renderer over JSSpeccy3

Project Goal

Transform the ZX Spectrum game Knight Lore into a modern browser-rendered experience by:

1. Running the original Z80 game logic unmodified.
2. Intercepting the dynamic semantic scene representation already generated by the game.
3. Bypassing the original Spectrum rendering pipeline.
4. Rendering the scene using modern JavaScript rendering techniques.

The architecture should preserve deterministic original gameplay while replacing only the presentation layer.

Core Architectural Insight

Knight Lore already builds a complete dynamic scene representation in RAM before rasterizing to the Spectrum framebuffer.

The correct interception point is not:

- VRAM at `0x4000`
- bitmap pixels
- ULA rendering

Instead, use the dynamic working memory generated by `RetrieveScreen` and related routines.

Key memory ranges from previous reverse engineering:

- Scratch/work memory:
  - `0x5BA0` - `0x6107`
- Dynamic room representation begins approximately at:
  - `0x5C88`
- Player body coordinates:
  - `0x5C09`
  - `0x5C0A`
  - `0x5C0B`
- Player head semantic coordinates:
  - `0x5C20`
  - `0x5C2A`
  - `0x5C2B`
- Player sprite bytes:
  - `0x5C41` for the head sprite
  - `0x5C45` for the body sprite
- Mirror/orientation flags:
  - `0x5C0F`
  - `0x5C2F`
- Current visual head X candidate:
  - `0x5C29`

Relevant JSSpeccy3 Components

`runtime/jsspeccy.js`

Main browser-side orchestration.

Responsibilities:

- Creates the Worker.
- Manages the browser frame loop.
- Receives frame buffers.
- Handles UI/audio/keyboard.
- Dispatches semantic frames to callbacks and event listeners.

Important section:

- `case 'frameCompleted'`

This is the main synchronization point between worker execution and browser rendering.

`runtime/worker.js`

Most important file for state extraction.

Contains:

- WASM core initialization.
- Emulator execution.
- Frame stepping.
- Access to WASM memory.
- CPU register access.
- Tape handling.
- Semantic RAM capture after frame execution.

Critical variables:

- `memoryData = new Uint8Array(memory.buffer)`
- `registerPairs = new Uint16Array(core.memory.buffer, core.REGISTERS, 12)`

The semantic extraction layer currently copies the target Z80 memory range with `core.peek(addr)`.

`runtime/knightlore.js`

Pure parser for copied Knight Lore RAM.

Responsibilities:

- Decode known player fields.
- Expose selected raw bytes.
- Parse tentative dynamic room/sprite records.
- Preserve diagnostic values separately from visual overlay helpers.

`runtime/render.js`

Current Spectrum framebuffer renderer.

Currently:

- `DisplayHandler.frameCompleted(frameBuffer)` renders the original ZX framebuffer.

Future renderer work should make this pipeline optional and allow:

- debug overlay renderer
- semantic renderer
- WebGL/Three.js renderer
- visual comparison mode against the original framebuffer

Development Strategy

- Keep the Z80/game logic untouched.
- Keep Spectrum rendering enabled while validating extraction.
- Extract copied RAM once per completed emulation frame.
- Render overlays on top of the original framebuffer until semantic positions are verified.
- Only bypass the Spectrum framebuffer after semantic reconstruction is reliable.
